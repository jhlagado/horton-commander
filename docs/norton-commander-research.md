# Norton Commander features used as references

The supplied screenshot captures the familiar arrangement: two directory
panels, an active file selection, menus, and an action strip. The earliest
Norton Commander reviews describe the same practical core: browse two file
collections, then view, edit, copy, rename, and delete selected files. Later
versions added many more shell, viewer, archive, and integration features.

Horton borrows the interaction idea rather than promising compatibility. Its
first scope is smaller because CP/M has a flat per-user file namespace, a
record-based file interface, a small transient program area, and no standard
child-process call that resumes the program which launched an editor.

References:

- [Norton Commander for IBM, Compute!, December 1986](https://www.atarimagazines.com/compute/issue79/Norton_Commander_For_IBM.php) — contemporary review of the original DOS release and its file-management, viewer/editor, and command functions.
- [Norton Commander review, REMark, 1989](https://www.vtda.org/pubs/REMark/1989/remark-volume10-issue2-1989.pdf) — contemporary description of the two-panel interface, command line, and function-key command bar.

These are historical references for feature selection, not specifications for
Horton.
